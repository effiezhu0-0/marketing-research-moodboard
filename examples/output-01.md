# 标准输出与验收样例

本文件为预期结构与验收说明，不是已执行的研究结果；不包含虚构反馈、来源或统计。

## 首轮响应

按 `../SKILL.md` 的模板展示五张独立 text 流程卡，沿用示例输入中已给出的项目资料、阶段限制和用途确认，不重复索取已提供信息。

## 默认证据确认板

首轮采集后必须交付 `证据确认板.md`，且早于趋势分析、方向提炼和最终视觉参考采集。板内每条材料仅标为：

- `视觉案例`：可包含会场页、模块、活动视觉、动效或设计稿；如实说明其可见来源属性和上线状态限制。
- `用户反馈`：只收录直接涉及会场、入口、权益理解、商品/类目承接或活动价值感知的表达。

每张卡至少包含：稳定编号、来源平台、载体、类型、截图/媒体预览、标题/账号/日期/可见互动信息、原话或事实、关联说明、限制、原帖链接及降级链接。板尾列出小红书、微博、用户之声的覆盖、检索词、排除项、缺口，并请求用户“保留 / 排除 / 补充”。

用户未确认保留证据前，不提出方向，不采集最终视觉参考。

## 确认后的交付形态

先在对话呈现三个候选方向及其已确认支撑证据；方向获确认后，交付：

`marketing-research-moodboard-double-11.html`

1. 项目摘要：项目目标、载体定义、研究执行日、精确24个月窗口、来源覆盖与限制。
2. 视觉趋势：规范、用户反馈、公开观察、编号洞察、机制成熟度及推断置信度、三个已确认方向及各自依据和风险。
3. 视觉参考：三个方向独立展示；每方向有足够合格素材时为5张灵感＋5张执行参考，桌面五列两行。每图保留完整构图、平台、可见日期、原始链接、角色、独立图注和入选理由。
4. 反面参考：四个不同载体风险的案例，说明排除理由。
5. 来源与版权页脚：实际访问和审阅数、失败原因、降级说明及审计链接。

## 通过条件

- 每条计数反馈或社交案例有真实完整来源截图；每个证据卡仅一个载体标签，原话、事实与解释可区分。
- 设计稿不得伪装为已上线页面；日期缺失、超出窗口或重复反馈不计数；参考图无可见日期时标明“日期未显示”。
- 图片不裁切，来源链接齐全，图文对应；不存在搜索缩略图或重建文本卡冒充原始证据。
- 在1440px和手机宽度检查通过，无破图、溢出、重叠、不可读文本。
- 素材不足按实际数量交付并说明原因，不添加虚构结果、重复图或无关参考；所有平台均无可用参考时说明阻塞和需要用户处理的访问问题。
